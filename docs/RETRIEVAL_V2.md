# 认知检索 v2：灰度启用与回退

这一版没有数据库迁移；默认继续使用已有关键词检索，不改变既有用户行为。
两个环境变量的取值只有 `1` 表示开启。

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `COGNITIVE_RETRIEVAL_V2` | 关闭 | 只注入有词法或语义相关性证据的记忆；无匹配时返回空 |
| `COGNITIVE_HYBRID_RETRIEVAL` | 关闭 | 需要同时开启 v2，才尝试加密记忆向量与查询 Embedding 的混合排序 |

建议先只开启 `COGNITIVE_RETRIEVAL_V2=1`，用历史标注问题评估 Precision@8、
Recall@8、空结果比例以及用户纠错情况；确认阈值适合当前数据后再开启
`COGNITIVE_HYBRID_RETRIEVAL=1`。关闭两个变量并重启服务即可回退。

混合模式只使用用户有权访问的模型（本人私有或全局）和他自己的记忆，
只选择相同 Embedding 模型、相同向量维度的结果。无已存向量、无模型、
解密失败或查询超时，都退回当前 v2 的关键词候选。查询臂给 650ms 截止，
不应把外部 Embedding 的长超时暴露给对话主链路。

阈值位于 `src/lib/cognitive/retrieval.ts`：
`RETRIEVAL_V2_KEYWORD_MIN = 0.18`、`RETRIEVAL_V2_COSINE_MIN = 0.78`。
这些数是保守初始配置，不是经过线上标注数据证明的最优值；上线前应做离线评测。

注意：混合模式会将用户本轮问题发送到所配置的 Embedding 提供商。
记忆正文仍以原有加密格式保存在 PostgreSQL。既有向量只在写记忆时
开启关联功能才会附加；历史记忆的全量向量补齐不在本次改造范围内。
