## 4. 集成测试覆盖明细（147 项）

脚本：`tests/run-integration.sh`。以下为各分组实际验证内容。

### 4.1 网络层 IP 白名单（登录前）

- 未授权 IP 在登录页、静态资源（`/_next/static/...`）、公开页与全部 API 上均被 403 拒绝，且发生在业务处理之前。
- 合法 IP 可正常访问；伪造 `X-Forwarded-For` 不能绕过（可信代理列表之外不采信转发头）。
- 删除规则后立即生效（受短 TTL 缓存约束，测试用 `IP_CACHE_MS=250`）。
- IPv4 与 IPv6（`::1`）规则分别验证。
- 默认拒绝：白名单为空时一律拒绝；网关不可用时应用 fail-closed。

### 4.2 认证、会话与 CSRF

- 登录成功/失败、错误密码计数与限流；会话 Cookie 为 HttpOnly，`SameSite=Lax`。
- 缺少/错误 CSRF 令牌的写请求被拒绝；跨站 Origin 被拒绝。
- 注销后会话立即失效；禁用用户后既有会话立即失效。
- 未登录访问 `/chat` 与普通用户访问 `/admin` 返回重定向而非页面内容。

### 4.3 注册、邮箱验证码与密码策略

- 注册需邮箱验证码；验证码 10 分钟有效、单次使用、错误 5 次后作废。
- 重复用户名/邮箱被拒绝；密码策略拒绝过短、常见密码、包含用户名/邮箱前缀的密码。
- 数据库中的密码为 Argon2id 哈希（`$argon2id$`，m=19456,t=2,p=1），无明文。

### 4.4 全局 AI 模型与 API Key 保护

- 管理员创建的全局模型 Key 在数据库中为 AES-256-GCM 密文。
- 模型列表 API 不返回 Key；前端页面源码/接口响应中无明文 Key。
- 提供商连通性测试通过（Mock `/models`）。

### 4.5 流式对话、持久化与加密存储

- SSE 流式返回，内容完整拼接后与预期一致。
- 对话与消息落库；会话标题、消息内容在数据库中以 `enc:v1:` 密文存储。
- 每会话可切换模型；用量（tokens）记录。
- 历史会话可读取、重命名、删除；删除后不可再访问。

### 4.6 上传、内容检查、加密、文档提取与语音

- 支持 PDF / DOCX / TXT / MD / CSV；扩展名与魔数校验，伪装文件被拒绝。
- 文件名、正文、分块文本均加密存储；磁盘文件带 `FAC1` 头与密钥 ID。
- 路径穿越、非法存储键、越权下载被拒绝。
- PDF/DOCX 文本提取后可进入上下文；长文档分块。
- STT（`/audio/transcriptions`）经 Mock 验证，返回文本进入消息流程。

### 4.7 多用户隔离与权限边界

- 用户 B 无法读取、下载、删除用户 A 的对话、消息与附件（404/403）。
- 普通用户访问任何 `/api/admin/*` 均被拒绝；伪造角色字段无效。
- 会话令牌、CSRF 令牌均不可跨用户复用。

### 4.8 管理员用户生命周期与会话控制

- 创建、禁用、启用、重置密码、撤销会话均生效；撤销后旧 Cookie 立即失效。
- 管理员敏感操作需要 `confirmPassword` 二次认证；错误密码被拒绝。
- 最后一个管理员 IP 的锁定保护：删除会导致自锁的规则被拒绝。
- 操作写入审计日志，审计内容不含密码/完整 Key。

### 4.9 账户设置、改密、改邮箱与找回密码

- 修改密码需旧密码；改密后其他会话被撤销。
- 修改邮箱需验证码；重复邮箱被拒绝。
- 忘记密码流程：验证码 → 重置 → 旧密码失效、旧会话失效。
- 个人资料读取/更新正常，越权更新他人资料被拒绝。

### 4.10 动态 IP 白名单、过期与防自锁

- IPv4/IPv6/CIDR 规则 CRUD；临时放行到期后自动失效。
- 规则变更后无需重启应用即生效；变更写入审计（操作者、前后值、时间、结果）。
- 防自锁：删除当前管理员来源 IP / 最后一条管理员可用规则被拒绝。
- 当前公网 IP 查询接口仅返回经可信代理校正后的地址。

### 4.11 加密备份、下载完整性与恢复

- 备份文件为 `FACBACKUP1` 格式，scrypt(N=1<<15) 派生 + AES-GCM 加密；错误口令无法解密。
- 下载校验和一致；备份内容不包含明文消息/Key。
- 恢复到独立数据库成功，恢复后登录、对话、附件均可读。
- `--db-only` 模式仅恢复数据库，不覆盖上传目录。

### 4.12 HTTPS/TLS、HSTS 与安全 Cookie

- TLS 1.2 与 TLS 1.3 握手均成功；服务端最低版本配置为 TLS 1.2（未单独发起 1.0/1.1 握手测试）。
- 生产模式下会话 Cookie 带 `Secure`；HTTP 环境下未显式允许时启动即失败。
- 响应含 HSTS、`X-Content-Type-Options`、`X-Frame-Options`、Referrer-Policy 与 CSP。
- HTTP→HTTPS 301 由 Nginx 配置验证（真实 Nginx 实验）。

### 4.13 主密钥轮换

- `rotate-keys --new-key-id it2` 将数据库密文与附件头迁移到新密钥 ID。
- 轮换后旧会话、消息、附件均可解密；旧密钥仅保留在密钥环中用于兼容。
- 轮换输出一次性新密钥材料，需人工保存，不写入数据库。

## 5. 真实 Nginx 网关联调（独立实验）

在沙箱内以 Nginx 1.18 加载 `deploy/nginx/family-ai-chat.host.conf` 的等价配置（仅移除不可用 IPv6 listen），后端为测试应用：

- 白名单来源：`200`，页面正常。
- 非白名单来源 `127.0.0.2`：`403`，返回品牌化拒绝页，未到达应用。
- `http://` 请求：`301` 跳转 HTTPS（ACME 路径除外）。
- HTTPS 响应 HSTS 头仅出现一次；`X-Forwarded-For` 被清空、`X-Real-IP` 由 Nginx 写入。

该实验证明 `auth_request /_ip_gate` 的默认拒绝与动态生效设计可按预期工作；生产需替换域名/证书并保留 `TRUSTED_PROXY_CIDRS` 仅含 Nginx 地址。

## 8. 未验证项（需在真实环境完成）

以下项目依赖本沙箱不具备的外部资源，代码与配置已就绪，但未做端到端验证，部署前必须逐项确认：

1. **Docker 镜像构建与 Compose 启动**：沙箱无 Docker daemon，未执行 `docker compose build/up`。首次部署请先在目标主机构建并查看 `docker compose logs app nginx db`。
2. **真实 SMTP 投递**：仅测试 console 传输；生产需配置 SMTP 主机/端口/账号并验证验证码邮件可达、退信处理。
3. **真实第三方 AI 提供商**：仅使用本地 OpenAI 兼容 Mock；未调用真实厂商 API，未验证其限流、超时、视觉/音频能力差异。上线前在后台“模型”页逐个测试连通性。
4. **云安全组 / 云防火墙**：仅提供文档与 nftables 模板，未在云账户中创建任何规则（按约定不购买、不修改云资源）。
5. **真实域名与 CA 证书**：仅验证自签证书与 Nginx 配置；未申请 Let's Encrypt 证书，未验证 DNS/80 端口挑战。
6. **Systemd 托管运行**：提供了 unit/timer/logrotate 文件，但沙箱无 systemd，未实际 `systemctl start` 验证。
7. **生产规模备份/恢复**：备份恢复在小型测试库验证；未验证大库耗时、磁盘空间与长时间停机窗口。
8. **真实语音输入（浏览器麦克风）**：STT 接口经 Mock 验证；未在真实手机浏览器验证麦克风权限与录音格式兼容性。
9. **邮件邀请链接的完整闭环**：邀请码创建/校验已测试；未接真实邮件服务做点击闭环。
10. **容器内 Nginx 1.27 与 `auth_request` 动态网关**：配置面向 1.27 编写，但实验使用 1.18；两者语法兼容性已人工核对，仍建议首次启动后执行 `docker compose exec nginx nginx -t`。
